# ASTRA · Venture Lab

Рабочий прототип веб-приложения для сборки и проверки бизнес-моделей на трёхмерной карте. Начальный сценарий — SaaS в России, рубли, УСН «Доходы» 6%; предполагаемый эквайринг — существующий терминал Т-Банка пользователя.

## Запуск

Требования: Node.js 22.12+ (в облачной среде проверен Node.js 24), npm, современный браузер. Зависимости зафиксированы в `package-lock.json`.

```bash
cd /workspace/ASTRA1
npm ci
npm run dev -- --port 5173 --strictPort
```

Для production-сборки:

```bash
npm run build
npm run preview -- --port 4173 --strictPort
```

Статические файлы находятся в `dist/`. Запуск development-сервера не публикует сайт в интернете. Сервер приложения и база данных на этом этапе не требуются. Шрифты поставляются локально, запросов к внешним сервисам во время работы приложения нет.

## Публикация через GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` устанавливает зависимости из lockfile, запускает тесты, собирает приложение с относительными путями и публикует только `dist/`. Он запускается при push в `main` или вручную через GitHub Actions. Банковские ключи и другие секреты для демоверсии не нужны.

Однократно включите **Settings → Pages → Build and deployment → Source → GitHub Actions** в репозитории `Harry777999/ASTRA1`. Затем запустите **Actions → Deploy ASTRA to GitHub Pages → Run workflow → main**. После успешного выполнения адрес опубликованной страницы появится в окружении `github-pages`. Если Pages недоступен для текущей видимости репозитория и тарифа, видимость репозитория не следует менять автоматически: сначала выберите подходящий вариант размещения.

Локальная подготовка той же сборки:

```bash
npm run build:pages
```

Публикация демоверсии не включает реальные платежи или передачу моделей на сервер. Проекты по-прежнему сохраняются в браузере; открыв сайт на другом домене, используйте JSON-экспорт и импорт для переноса.

## Что работает

- Настоящая WebGL-сцена на Three.js: блоки, направленные связи, движение потока, выбор, перетаскивание и масштабирование. Если WebGL недоступен, показывается доступный для управления список.
- Семь типов блоков: привлечение, аудитория, SaaS-продукт, подписка, ИИ-ассистент, бухгалтерия и юридическое сопровождение. До 30 блоков на модель.
- Добавление, настройка и удаление блоков, создание и удаление связей, отмена до 30 изменений.
- Изменяемая экономика: посетители, конверсия, цена, отток, начальные клиенты, расходы на клиента, постоянные расходы и стартовый капитал.
- Прогноз на 12 месяцев: выручка, клиенты, расходы, УСН, прибыль и денежный остаток.
- Три локальных помощника по заданным правилам. Сценарий снижения оттока применяется только нажатием пользователя; доступна отмена.
- Сохранение в `localStorage`, экспорт и проверяемый импорт JSON. Файлы с некорректными числами, блоками и связями не заменяют текущий проект.
- Адаптивный интерфейс на русском языке, управление формами с клавиатуры, диалоги с удержанием фокуса.
- Раздел Т-Банка с честным статусом подключения и планом интеграции.

Выберите блок на карте, чтобы настроить его. Кнопка «Соединить на карте» создаёт направленную связь с выбранным следующим блоком; также можно выбрать назначение из списка. Для создания выручки необходима полная цепочка **Привлечение → Аудитория → SaaS-продукт → Подписка**.

## Допущения расчёта

Для каждого месяца:

```text
клиенты = прошлые клиенты × (1 − отток / 100) + посетители × конверсия / 100
выручка = клиенты × цена подписки
расходы = сумма постоянных расходов всех блоков + клиенты × расходы на клиента
УСН = выручка × 0,06
прибыль модели = выручка − расходы − УСН
денежный остаток = предыдущий остаток + прибыль модели
```

Первый месяц начинается с указанного количества начальных клиентов. Отток применяется к предыдущим клиентам; новые клиенты оплачивают полный месяц. Дробное число клиентов — математическое ожидание; в интерфейсе оно округляется только для отображения. Одинаковые блоки не умножают входящий поток: параметры воронки общие на весь проект. Постоянные расходы несвязанных блоков также учитываются. Если полной цепочки нет, клиенты и выручка равны нулю, но расходы остаются.

УСН начисляется в прогнозе ежемесячно для сопоставления показателей; это не календарь перечисления налогов. Модель не учитывает уменьшение УСН на страховые взносы, сами взносы, НДС, лимиты применения налогового режима, комиссии эквайринга, возвраты, сезонность, отсрочки и кассовый метод учёта реальных поступлений. Комиссии пока можно включать в расход на клиента вручную. Прогноз не заменяет бухгалтерский учёт или юридическую проверку.

## Что ещё не подключено

Нет реальных платежей, рекуррентных списаний, кассы, отчётности, внешнего ИИ, авторизации, облачного хранения или неизменяемого аудиторского журнала. Блок «ИИ-ассистент» учитывает бюджет, а не выполняет задачи. Финансовый и юридический блоки учитывают расходы, но не оказывают соответствующие услуги.

Проект сохраняется только в браузере. Очистка браузерных данных удаляет сохранение, поэтому используйте экспорт. Не храните пароли, данные карт, API-ключи и персональные данные клиентов в названиях блоков или JSON. В этой версии нет полей для секретов.

## Проверка

```bash
npm test
npm run build
npm run test:e2e
```

Unit-тесты проверяют финансовые формулы, УСН в убыточном сценарии, крайние значения оттока, направление связей и валидацию импортируемых проектов. Playwright проверяет WebGL, редактирование графа, сохранение, импорт/экспорт, сценарии помощников и мобильный интерфейс.

В облачной среде Playwright использует `/usr/bin/chromium` с программным WebGL. Для другого установленного Chromium задайте `CHROMIUM_PATH=/absolute/path/to/chromium`. Тестовый сервер запускается автоматически на порту 5173; уже работающий сервер разработки может использоваться повторно. Снимки экрана создаются в игнорируемом каталоге `test-results/`.

## Структура

- `src/model.ts` — схема проекта, каталог блоков, расчёт и валидация импорта.
- `src/World.tsx` — Three.js, взаимодействие с 3D-сценой и освобождение GPU-ресурсов.
- `src/App.tsx` — конструктор, экономика, помощники, подключения и сохранение.
- `src/styles.css` — адаптивный интерфейс.
- `src/model.test.ts`, `tests/workspace.spec.ts` — unit- и браузерные проверки.
- `ROADMAP.md` — дальнейшее развитие до операционной системы реального бизнеса.
